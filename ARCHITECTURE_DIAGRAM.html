FlowBudget architecture

Svelte 5 + Vite SPA. Components render from three reactive store singletons, which write to a local cache immediately and push changes to Supabase through a persistent sync queue. Components also talk to each other through a small pub/sub signal bus.

Hover a box to trace its connections (labels show the members used). Click to pin, click empty space to clear. Scroll to zoom at the cursor; hold Space and drag (or middle-drag) to pan.

Key flows

1 · Boot & auth

  1. index.html loads main.js → mount(App, #app).
  2. Importing the stores constructs singletons that hydrate from localCache (transactions, goals, recurring, queue).
  3. App reads localCache.loadSession(). Cached user → render UI immediately with the "Syncing…" pill; none → spinner.
  4. connect() → auth.getCurrentUserResult(): live user → activate(); offline with cached user → keep cache, scheduleReconnect() (15s); otherwise signOutLocally() → AuthScreen.
  5. activate(): reset data if the user id changed, save session, syncQueue.setReady(true), then budgetApi.sync() → goalsApi.sync() → recurringApi.sync().
  6. AuthScreen calls signIn/signUp; the onAuthStateChange listener in App fires SIGNED_IN → activate().

2 · Write path (add / edit transaction)

  1. MonthView / WeekCard / TransactionList emit OPEN_TRANSACTION_FORM.
  2. TransactionForm (subscribed) opens and pre-fills the form.
  3. On submit: budgetApi.addTransaction() or updateTransaction(id), then emit UPDATE_TRANSACTION.
  4. Store mutates $state → #queueUpsert → syncQueue.enqueue('transactions','upsert',id,snapshot) + #persist → localCache.saveTransactions.
  5. enqueue collapses older ops for the same id, saves the queue, calls flush().
  6. #drain → databaseApi.upsert/delete → flowbudget_<table>. Offline → pause; other errors retried up to 3× then dropped; leftovers retried after 15s or on online.
  7. WeekCards receive UPDATE_TRANSACTION → updateTransactionData() re-queries getTransactionsForWeek.

3 · Sync (pull) & sign-out

  1. store.sync() de-dupes concurrent calls via this.syncing.
  2. #sync: await syncQueue.flush() → databaseApi.getAll(table).
  3. syncQueue.applyTo(table, rows) replays still-pending ops so unsynced local edits survive.
  4. Replace store array, #persist, emit <TABLE>_FETCH_ALL (only TRANSACTIONS_FETCH_ALL has a subscriber).
  5. Sign-out / SIGNED_OUT / rejected session → resetData(): setReady(false), every store reset(), syncQueue.clear(), localCache.clear().

Things noticed while mapping

  • GoalsView and RecurringView copy the store array into local $state once. sync() reassigns the store array, and nobody subscribes to GOALS_FETCH_ALL / RECURRING_FETCH_ALL, so fresh cloud data won't show until the view remounts (GoalsView also catches UPDATE_GOALS, but only delete emits it).
  • recurringApi.addRecurring builds { id, amount, frequencyDays } and drops name, which RecurringForm sets.
  • The edit branch of RecurringForm.handleSubmit is empty, and the RecurringView "Edit" button has no handler yet (work in progress).
  • syncQueue.enqueue collapses pending ops by id only, not by type+id. That's harmless with UUIDs but worth knowing.
  • App.svelte reads and writes darkMode in localStorage directly, so localCache.clear() leaves it alone.
